# 🍚 今天吃什么 —— 转盘小工具

一个给你女朋友决定「今天吃什么」的 H5 转盘。点一下转盘，随机转出一个结果；
你和她都可以随时增删菜品、调概率。**零依赖、零构建、零费用**。

- 前端：Vue 3（官方生产版本已经放在 `vendor/` 里，**不需要 npm install，也不需要打包**）
- 动画：Canvas 画转盘 + CSS 旋转 + 手写缓动，中奖撒彩带
- 存储：`localStorage`，改完自动保存在手机上
- 部署：直接把整个文件夹丢给 Cloudflare Pages / GitHub Pages，0 元/年

---

## 1. 本地先看一眼（30 秒）

需要电脑上有 Node.js（18 以上即可，只用它当静态服务器，不装任何依赖）：

```bash
npm start
```

然后打开 <http://localhost:5173/>。

手机上试玩：终端会打印一个 `http://192.168.x.x:5173/` 的地址，
手机连同一个 WiFi 就能打开 —— **这已经和部署后的效果完全一样了**，先试试手感。

> 不想用 npm 也行：`node scripts/serve.mjs`，效果一样。
>
> ⚠️ **不要直接双击 `index.html`**：地址会变成 `file://` 开头，浏览器禁止这种页面加载程序脚本，会白屏。
> （真双击了也不会看到空白——页面会明确告诉你「需要用网址打开」。）

## 2. 部署（二选一，都免费）

部署的内容就是**这个文件夹本身**，没有 `dist/`、不需要 `npm run build`。

### 方案 A：Cloudflare Pages（推荐，国内访问通常更顺）

1. 注册/登录 <https://dash.cloudflare.com/>（免费账号即可）。
2. 左侧 **Workers & Pages → Create → Pages → Upload assets**（直接上传文件夹，不用 Git）。
3. 项目名随便取，例如 `what-to-eat`；把**整个文件夹**里的内容拖进去上传
   （至少要包含 `index.html`、`src/`、`vendor/`）。
4. 点 **Deploy**，几十秒后会给你一个地址：

   ```
   https://what-to-eat.pages.dev
   ```

   这个地址就是最终链接，可以直接发微信。

> 想以后改一下自动更新，就把这个文件夹传到一个 GitHub 仓库，
> 然后在 Cloudflare Pages 里选 **Connect to Git**：构建命令留空，输出目录填 `/`（根目录）即可。

### 方案 B：GitHub Pages

1. 在 GitHub 新建一个仓库，例如 `what-to-eat`（Public）。
2. 把这个文件夹里的所有文件传上去（网页上 **Add file → Upload files** 拖进去就行）。
3. 仓库 **Settings → Pages**：
   - Source 选 `Deploy from a branch`
   - Branch 选 `main`，目录选 `/ (root)`，Save
4. 等 1～2 分钟，地址是：

   ```
   https://你的用户名.github.io/what-to-eat/
   ```

   注意：**地址最后一定要带斜杠 `/`**，否则会 404。

本项目资源全部用相对路径（`./src/...`、`./vendor/...`），
所以放在子目录（GitHub Pages）或根目录（Cloudflare Pages）都能正常打开，不用改任何配置。

### 方案 C：用 Git 推送（推荐，以后改一行就能自动重新部署）

这个文件夹**已经是一个 git 仓库并且提交好了**（一个 commit，22 个文件），所以只要：

```bash
cd E:\file\whatToEat

# 1) 在 GitHub 网页上新建一个空仓库（不要勾选 README / .gitignore）
# 2) 把下面这行换成你自己的仓库地址，然后执行
git remote add origin https://github.com/你的用户名/what-to-eat.git
git branch -M main
git push -u origin main
```

推送完再做一次二选一：

- **GitHub Pages**：仓库 Settings → Pages → Source 选 `Deploy from a branch`，
  Branch 选 `main` + `/ (root)` → Save。
- **Cloudflare Pages**：Workers & Pages → Create → Pages → **Connect to Git** → 选这个仓库，
  **Framework preset 选 None，Build command 留空，Build output directory 填 `/`** → Save and Deploy。

以后想改菜单/配色，只要 `git add -A && git commit -m "改了点东西" && git push`，平台会自动重新部署。

> 说明：本项目是零构建的，**没有 `dist/` 之类的「构建产物」**——需要部署的产物就是当前这些文件本身
> （`index.html` + `src/` + `vendor/`），这也是它部署起来最省事的原因。

### 关于费用和域名

- 上面两种方案都在免费额度内，**0 元/年**；不买独立域名也可以一直用平台给的地址。
- 想更好记可以以后再加域名（`*.pages.dev` 也能一直用）。
- 如果女朋友那边 Cloudflare 的 `pages.dev` 打开很慢，可以两个平台都部署一份，挑快的那个发给她。

## 3. 怎么用

| 想做的事 | 怎么操作 |
| --- | --- |
| 转一次 | 点转盘中间的**「开始」**按钮（或下面的「开始转」） |
| 加菜品 | 右上角 **☰** → 输入框里写菜名 → 「添加」；也可以点下面的快捷标签一键添加 |
| 删菜品 | 列表里那行右边的 **✕** |
| 改菜名 | 直接点列表里的菜名改，改完点一下别处 |
| 调概率 | 每行的 **＋ / −**，默认都是 1（一样容易中）；调到 0 就等于不会被抽到 |
| 所有菜一样容易中 | 打开「所有菜等概率」开关（默认按上面设的权重来） |
| 打乱顺序 | 抽屉底部「打乱顺序」 |
| 恢复默认菜单 | 抽屉底部「恢复默认菜单」 |
| 关声音 | 关掉「音效」开关 |

小细节：

- 每转一次都会**重新洗牌**，所以看起来不会老停在同一个位置，也更公平。
- 概率是「先按权重抽好中奖者，再让转盘停到它上面」，所以指针停下的位置和弹窗结果**一定一致**。
- 音效是用 WebAudio 现场合成的，没有音频文件；部分浏览器（尤其 iOS 静音键打开时）可能没声音，不影响使用。

### 数据存在哪？

存在**她这台手机的浏览器本地**（`localStorage`）：

- 同一个微信/浏览器打开，菜品会一直在；
- 换手机、换浏览器、清理缓存/清除微信数据 → 需要重新添加；
- 两个人各改各的，互不影响（这是纯前端方案，没有服务器）。

> 想手动备份：在管理面板里把菜名抄一份就行；或者在浏览器控制台执行
> `copy(localStorage.getItem('what-to-eat-wheel:v1'))` 保存下来。

## 4. 微信里打开的注意事项（重要）

**功能上没问题**：这就是个普通 HTTPS 网页，微信内置浏览器（iOS WKWebView / Android X5）能正常打开、
转盘、点按钮、存数据都没问题（已经在真机内核上验证过 ES Module 和 Canvas 的兼容性）。

实际会遇到的是**平台层面的限制**，提前知道就好：

1. **链接可能被折叠/提示**：微信对陌生域名有时会提示「即将离开微信」，点继续即可。
2. **域名被拦截的可能**：`pages.dev`、`github.io` 在部分地区/某些网络下访问不稳定。
   如果她打不开，优先试这两个办法：
   - 换成另一个平台的地址（A/B 各部署一份，挑能开的那个发）；
   - 把网页加到手机主屏（Safari / Chrome「添加到主屏幕」），当小 App 用，打开更快也更稳。
3. **朋友圈/公众号限制**：本工具不需要登录、不需要公众号，直接发聊天窗口的链接即可。
4. **首次打开建议你先自己试**：用你自己的手机、她的手机各打开一次，确认能转、能存。

如果以后想彻底避开这些问题（自定义域名 + 备案），成本就上去了，和「0 元方案」冲突，暂时不推荐。

## 5. 项目结构

```
whatToEat/
├── index.html                 # 页面入口（相对路径引资源，放子目录也能用）
├── vendor/
│   └── vue.global.prod.js     # Vue 3.5.44 官方生产版本（本地文件，不依赖 CDN）
├── src/
│   ├── main.js                # 启动：注入样式、注册组件、挂载
│   ├── App.js                 # 根组件：状态、转动动画、布局
│   ├── components/
│   │   ├── WheelCanvas.js     # Canvas 画转盘 + 中间「开始」按钮
│   │   ├── PointerMark.js     # 顶部指针
│   │   ├── ListItemPanel.js   # 菜品编辑抽屉
│   │   ├── ResultOverlay.js   # 中奖弹窗
│   │   └── ConfettiFx.js      # 彩带粒子
│   └── utils/
│       ├── wheelMath.js       # 纯逻辑：按权重抽奖 + 转到哪个角度（有测试覆盖）
│       ├── storage.js         # localStorage 读写与数据校验
│       └── constants.js       # 配色、默认菜单、震动/音效
├── tests/                     # 自检脚本（不需要联网、不需要装包）
└── scripts/serve.mjs          # 本地预览服务器（Node 内置模块，零依赖）
```

### 为什么没有 webpack / Vite？

因为需求是「简单、免费、别折腾」：不打包就没有构建步骤、没有 `node_modules`、
也不会有「框架要从 CDN 加载」的风险。组件用 Vue 的运行时编译器 + 模板字符串，
打开 `index.html` 就直接跑。想换成 Vite + `.vue` 单文件组件也完全可以，
但那样每次部署前都要多一步 `npm run build`。

## 6. 自检

```bash
npm test      # 22 项纯逻辑测试：抽奖权重、角度计算、数据校验
npm run check # 上面 + 25 项渲染自检 + 42 项结构自检，共 89 项
```

三类自检都不需要浏览器、不需要联网、不需要装任何依赖：

1. **纯逻辑测试**（`tests/run.mjs`）：权重抽奖的比例是否符合预期、0 权重永远不会被抽中、
   转盘最终角度是否把中奖扇区对准指针、角度是否永远单调向前（不会倒着转）、
   本地存储的数据校验与去重。
2. **渲染自检**（`tests/render.mjs`）：用一套极简 DOM 实现把**真实的 Vue 生产版本**和全部组件跑一遍，
   验证模板能编译、应用能挂载、添加/删除/改名/调权重/转动/结果弹窗都正常，
   并且用「录像机」式 canvas 上下文**检查转盘真的画出了 16 个等角扇形、圆心给指针留了位置、
   每个菜名都画上且没有超出扇区、配色正常循环**。
3. **结构自检**（`tests/structure.mjs`）：检查所有源码括号/引号/CSS 配平、相对 import 与 HTML 引用的文件
   都真实存在、双击打开时的提示守卫、以及没有把多余产物混进项目。

想真机试玩：`npm start`，然后用手机的浏览器打开终端里打印的局域网地址。

## 7. 想再改点什么

- **换默认菜单**：`src/utils/constants.js` 里的 `DEFAULT_DISHES`。
- **换配色**：同文件的 `PALETTE`。
- **转得更久/更短**：`src/App.js` 里 `spin()` 的 `spinDuration`（毫秒）。
- **转动圈数**：`src/App.js` 里 `buildSpin(..., { turns: 6 })`。
- **改完必须做的事**：直接刷新页面就生效（没有构建步骤），但注意浏览器可能缓存，
  微信里如果没变化，可以关掉页面重新从聊天记录点开，或在链接后加 `?v=2`。
